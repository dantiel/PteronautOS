## Architecture Overview

The i18n system is an **event-driven, singleton-based translation engine** built for LitElement Web Components. It uses a two-tier architecture:

```
┌─────────────────────────────────────────────────────────┐
│                    I18nEngine (Singleton)                │
│  ┌──────────┐  ┌──────────┐  ┌──────────────────────┐  │
│  │ _locales │  │ _strings │  │ localStorage         │  │
│  │ Map<code,│  │ Map<key, │  │ 'pteronautos-locale' │  │
│  │  module> │  │  value>  │  │                      │  │
│  └──────────┘  └──────────┘  └──────────────────────┘  │
│                                                         │
│  t(key, params) → string     setLocale(code) → void     │
│  init() → void               locale → string            │
│  availableLocales → []       dir → 'ltr'|'rtl'          │
└──────────┬──────────────────────────────────────────────┘
           │ window 'locale-changed' CustomEvent
           ▼
┌──────────────────────────────────────────────────────────┐
│  Panels (LitElement Web Components)                      │
│  ┌────────────┐  ┌──────────────┐  ┌─────────────────┐  │
│  │ Vanilla JS │  │ CoffeeScript │  │ LithAML         │  │
│  │ i18n.t()   │  │ i18n.t()     │  │ self._t()       │  │
│  └────────────┘  └──────────────┘  └─────────────────┘  │
└──────────────────────────────────────────────────────────┘
```

### Design Principles

| Principle | Implementation |
|-----------|---------------|
| **Zero dependencies** | Pure ES module, no external libraries |
| **Reactive** | `locale-changed` CustomEvent triggers LitElement re-renders |
| **Failsafe** | Three-tier fallback: active locale → English → bare key |
| **RTL-ready** | `document.documentElement.dir` set per locale |
| **Persistent** | Locale choice survives refresh via localStorage |
| **Browser-aware** | Auto-detects `navigator.language` on first visit |

## API Reference

### Import

```javascript
// ES module import (all contexts)
import { i18n } from '../utils/i18n.js';

// CoffeeScript
import { i18n } from '../utils/i18n'
```

### Core Methods

#### `i18n.t(key, params?)` → `string`

Translate a key. Supports `{{param}}` interpolation. Falls back through the chain: active locale → English → bare key.

```javascript
// Simple translation
i18n.t('elrs.binding.title')                // → "Binding"

// Interpolation
i18n.t('elrs.wifi.ap_mode', {ssid: 'Ptero'}) // → "AP Mode: Ptero"

// Dynamic keys (e.g., UID type names)
i18n.t(this.uidData.i18nKey)                 // → "ExpressLRS UID"
```

#### `i18n.setLocale(code)` → `void`

Switch active locale. Persists to localStorage, dispatches `locale-changed` CustomEvent, sets `document.documentElement.dir` for RTL.

```javascript
i18n.setLocale('ja');  // Switch to Japanese
i18n.setLocale('ar');  // Switch to Arabic (auto-enables RTL)
```

#### `i18n.init()` → `void`

Initialize — called once after all locale modules are registered. Auto-detects locale: localStorage → `navigator.language` → `'en'`.

#### `i18n.locale` → `string`

Current locale code (e.g., `'en'`, `'ja'`, `'ar'`).

#### `i18n.availableLocales` → `Array<{code, name, nativeName, dir}>`

All registered locales for UI selector rendering.

#### `i18n.dir` → `'ltr' | 'rtl'`

Text direction for current locale.

### Convenience

```javascript
// Console debugging
window._t('elrs.binding.title')              // → "Binding"
```

## Usage Patterns

### Pattern 1: Vanilla JS LitElement Panel

```javascript
import { i18n } from '../utils/i18n.js';

class MyPanel extends LitElement {
    render() {
        return html`
            <div class="mui-panel">
                <h1>${i18n.t('elrs.my_panel.title')}</h1>
                <p>${i18n.t('elrs.my_panel.description', {count: this.itemCount})}</p>
            </div>
        `;
    }
}
```

### Pattern 2: With unsafeHTML (when locale strings contain HTML)

```javascript
import { i18n } from '../utils/i18n.js';
import { unsafeHTML } from 'lit/directives/unsafe-html.js';

class MyPanel extends LitElement {
    render() {
        return html`
            <div>
                ${unsafeHTML(i18n.t('elrs.my_panel.help_html'))}
                <!-- Renders: "Connect <b>TX</b> module<br/>to USB port" -->
            </div>
        `;
    }
}
```

**Use `unsafeHTML` only when the locale string contains legitimate HTML** (`<br/>`, `<b>`, `<ul>/<li>`, etc.). Never use it with user-supplied data — Lit auto-escapes all `elrsState.*` values automatically.

### Pattern 3: Dynamic Keys (UID types)

```javascript
// Define UID options with i18n keys
const UID_CONFIG = [
    {value: 0, i18nKey: 'elrs.binding.uidtype.expresslrs', label: ''},
    {value: 1, i18nKey: 'elrs.binding.uidtype.pmr', label: ''},
    // ...
];

// Render with dynamic key lookup
${UID_CONFIG.map(item => html`
    <option value="${item.value}">
        ${i18n.t(item.i18nKey)}
    </option>
`)}
```

### Pattern 4: Getter Functions for Constant Arrays

When a `const` array needs i18n (e.g., button action options), convert to a getter function:

```javascript
// BEFORE (hardcoded):
const ACTION_OPTIONS = [
    {value: 0, label: 'No Action'},
    {value: 1, label: 'Toggle WiFi'},
];

// AFTER (i18n via getter):
get ACTION_OPTIONS() {
    return [
        {value: 0, label: i18n.t('elrs.buttons.action_no_action')},
        {value: 1, label: i18n.t('elrs.buttons.action_toggle_wifi')},
    ];
}
```

### Pattern 5: checkChanged() Safety

Always compare against raw data (`elrsState.*`), never against translated strings:

```javascript
checkChanged() {
    // ✅ CORRECT: Compare against raw state
    return elrsState.config.uid.toString() !== this.originalUID.toString() ||
           elrsState.settings.ssid !== this.originalSsid;

    // ❌ WRONG: Comparing against translated labels
    // Never: i18n.t('elrs.xxx') !== someTranslatedLabel
}
```

### Pattern 6: CoffeeScript + LithAML Panels

```coffeescript
# CoffeeScript (ornithopter-panel.coffee)
import { i18n } from '../utils/i18n'

export default class OrnithopterPanel extends PteroElement
  _t: (key, params) -> i18n.t(key, params)
```

```haml
/ LithAML (ornithopter-panel.lithaml)
.mui-panel
  %h1= self._t('ornithopter.panel.title')
  %label= self._t('ornithopter.waveform.frequency', {hz: @frequency})
```

## Security Model

The i18n system was audited (Validatio, Step 9) with zero vulnerabilities found:

| Check | Result |
|-------|--------|
| `eval()` usage | **None** — no dynamic code execution |
| `innerHTML` / `dangerouslySetInnerHTML` | **None** — zero occurrences |
| `unsafeHTML` with user data | **Safe** — all 14 call sites use locale strings, never `elrsState.*` |
| URL injection | **Safe** — all `href`/`src` attributes are hardcoded |
| localStorage access | **Safe** — wrapped in try/catch |
| Locale file integrity | **Clean** — zero brace mismatches, zero `<script>` tags |
| Key interpolation | **Safe** — regex `\{\{(\w+)\}\}` only replaces known params |

**LitElement's template system auto-escapes all interpolated values.** The only HTML rendering path is through `unsafeHTML()` on locale strings that intentionally contain markup like `<br/>` or `<b>`.

## Adding a New Locale

1. **Create locale file** at `src/html/src/locales/XX.js`:

```javascript
// Icelandic — PteronautOS WebUI
export default {
  code: 'is',
  name: 'Icelandic',
  nativeName: 'Íslenska',
  dir: 'ltr',  // or 'rtl' for Arabic, Hebrew, etc.
  keys: {
    // Copy all keys from en.js and translate values
    'app.brand.pteronaut': 'PTERONAUT',
    'app.brand.os': 'OS',
    // ... all 356 keys
  }
};
```

2. **Register** by importing in the locale loading chain — the engine auto-discovers via `register()`.

3. **All keys must be present** — missing keys fall through to English, but for build-time integrity, every locale should have the complete key set.

1. **Add to `en.js`** first (English is the base locale):

```javascript

'elrs.new_panel.description': 'Configure the {{device}} settings.',
```

3. **Use in code:**


## Troubleshooting

### "i18n is not defined" or "Cannot read property 't'"

Ensure the import is correct:

```javascript
import { i18n } from '../utils/i18n.js';  // Named import, lowercase
```

### Key returns as bare string (e.g., `elrs.binding.title`)

- Check that `i18n.init()` has been called (handled in `app.js`).
- Check that the locale module is registered.
- Check that the key exists in both the active locale and `en.js` (fallback).

### unsafeHTML rendering raw HTML tags

Ensure `unsafeHTML` is imported and used **as a directive** on the return value:

```javascript
import { unsafeHTML } from 'lit/directives/unsafe-html.js';
// ...
${unsafeHTML(i18n.t('elrs.update.bin_gz_warning'))}  // ✅
${i18n.t('elrs.update.bin_gz_warning')}              // ❌ renders literal <br/>
```

### RTL not applying

- Check the locale file has `dir: 'rtl'`.
- Check that `i18n.setLocale()` is called (not just localStorage manipulation).
- Verify `document.documentElement.dir` in DevTools.

### Build error: duplicate key

Run from `src/html/`:

```bash
node -e "
const en = require('./src/locales/en.js').default;
const keys = Object.keys(en.keys);
const dupes = keys.filter((k,i) => keys.indexOf(k) !== i);
console.log('Duplicates:', dupes);
"
```
