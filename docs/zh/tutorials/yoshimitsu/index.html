YOSHIMITSU — 完整解决方案：所有秘籍，一卷尽藏

一个草图，两块开发板，六种架势。YOSHIMITSU 是完整的赫尔墨斯方案 — CRSF→PWM 转换器（KINCHO）、Zephyrus 陀螺仪悬浮（MANJI_DRAGONFLY）、EP2 口袋刷写器（FLEA · MEDITATION）、无刀工作台（NSS）、永不回头的镜子（BACK_TURNED）— 加上 YOSHI 极光与讲述一切的冥想管理员 JIGUANG。

一块板，六个架势

YOSHIMITSU 是拥有六种架势的隐密忍者——一个灵魂，而非两件工具。单个草图即可编译两块板子；架势通过 USB 命令、GPIO0 按钮（ESP32-S3）或 RESET 连按（RP2040-Tiny）切换：

架势 含义
KINCHO CRSF→PWM 转换器——格挡（CRC 弃绝虚假）。无通道名，无陀螺仪。
MANJI_DRAGONFLY 转换器 + Zephyrus 陀螺链接（可选 MPU6050）——悬浮。
FLEA 电源循环治具——把 RX 送入引导加载程序的托举。
MEDITATION 口袋刷写器——海绵头，蓄能待刷。
NSS 无刀工作台——USB 直驱舵机，无射频。
BACK_TURNED 欺人的静息——一面活的 UART 之镜。永不回望。

一个草图，两个目标：sketches/yoshimitsu/yoshimitsu.ino 可为 Waveshare RP2040-Tiny（最轻，无板载按钮）以及任何原生 USB 的 ESP32-S3 编译，使用标准 arduino-pico / arduino-esp32 内核。

YOSHIMITSU — 组合固件

YOSHIMITSU 是推荐固件。它以 KINCHO（转换器）启动并在架势间移动。USB 控制台是两块板上的规范开关——KINCHO → MANJI → FLEA → MEDITATION → NSS → BACK → POSE <n>。在 ESP32-S3 上，BOOT 按钮（GPIO0）是第二表面：

情境 手势 动作
任意架势 双击 循环 KINCHO → MANJI → NSS → BACK → KINCHO →
任意架势 长按 2 秒 进入 MEDITATION
MEDITATION / FLEA 单击 重启接收机（运行新固件）
MEDITATION / FLEA 双击 FLEA——把接收机送入引导加载程序

接线是一副永久线束——同样的导线服务于每一种架势，因此飞行与刷写之间永不需要重新接线。MEDITATION 中 USB→UART 通路是纯透明桥（无行解析），esptool 的二进制 SLIP 流量原样穿过。完整源码：sketches/yoshimitsu/yoshimitsu.ino（配置外壳）与 src/Yoshimitsu.h（库核心）。

库加密狗——更新而不必重动配置

YOSHIMITSU 遵循蓝鸦策略（Gralha Azul）：整个文件夹就是一个库加密狗。草图 sketches/yoshimitsu/yoshimitsu.ino 只是一层薄薄的配置外壳（引脚、标志、BOARD_CUSTOM 块）；隐密忍者的全部住在 src/Yoshimitsu.h，而所有默认值住在 src/Yoshimitsu_Padraos.h（帕德罗因斯）。更新加密狗：在库文件夹里 git pull——或放入新版本——你的配置草图原封不动。作为 Arduino 库安装一次（符号链接或复制进 libraries 文件夹），固件更新就再也不是重新接线，也再不是重新配置。

  • `src/Yoshimitsu.h`——整个核心：架势、CRSF、MUSHIN、JIGUANG、刷写桥。
  • `src/Yoshimitsu_Padraos.h`——所有默认值（引脚、时序、栅极电平）作为 `*_PADRAO` 值。
  • `library.properties`——Arduino 库清单（版本、架构）。
  • `yoshimitsu.ino`——仅你的配置；在 include 之前定义即可覆盖任何东西。

KINCHO — CRSF→PWM 转换器

KINCHO——转换器架势——以 420 000 baud 在 UART 上读取 CRSF，以 172–1811 通道范围映射出的 988–2012 µs 窗口驱动舵机，并以 500 ms 失控保护居中。格挡即 CRC 校验：损坏的帧在碰到舵机之前即被丢弃。转换器与通道无关——舵机是 SERVO_PIN_1..8，CHANNEL_TO_SERVO 表决定哪个 CRSF 通道供给哪只；通道的含义属于混控器/内核，从不属于板子。

  • ESP32-S3：RX TX → GPIO44，RX RX → GPIO43，共地，共享 5 V 轨。
  • RP2040-Tiny：RX TX → GPIO1（UART0），共地。
  • 舵机：`SERVO_PIN_1..3`（S3 上还有三只）——可在 PIN MAP 块中改写。

对于陀螺稳定的扑翼机，使用 MANJI_DRAGONFLY——同样的转换器加上 Zephyrus 链接：GYRO_SDA/GYRO_SCL 上的可选 MPU6050 将偏航速率修正送入冠羽舵机。未接陀螺仪时，MANJI_DRAGONFLY 优雅降级为 KINCHO。商用 CRSF→PWM 转换板根本没有陀螺通路——EP2 级接收机不携带 IMU，所以 Zephyrus 活在 YOSHIMITSU 之中，而非接收机之中。

如果你的接收机已经会说 PWM（5 ch 或 7 ch 板），就完全不需要转换器架势——此时下方的 MEDITATION 是你拥有 S3 的唯一理由。

KINCHOI — EP2 级接收机口袋烧录器

问题：EP2 级接收机（HappyModel EP2、EP1、EPW6……）在堡形焊盘上引出 CRSF，并带有一个极小的 BOOT 焊盘。使用 FTDI 适配器意味着在通断电接收机的同时把探针抵在两块 1 mm 焊盘上——别扭，而且每次固件更新都要重新焊接或重新夹线。

方案：让 ESP32-S3 成为刷写器。一个 GPIO 将接收机的 BOOT 焊盘拉低；一个小型 P-MOSFET 在软件控制下切换接收机的 3.3 V 电源轨；USB 口变成串口。按下 S3 上的一个按钮，它便执行那套精确的通断电之舞，把 ESP8285 送入其 ROM 引导加载程序——然后 esptool 直接穿过桥接写入。无需 FTDI，无需探针，无需反复焊接：把接收机焊盘一次焊到一条短线尾上，永远复用。

零件清单：

零件 典型型号 成本
ESP32-S3 微型板（原生 USB） Waveshare ESP32-S3-Tiny / -Micro / -Nano 约 6 美元
P 沟道逻辑电平 MOSFET AO3401（SOT-23），小型转接板 约 1 美元

桥接适用于任何引出 TX、RX、3V3、GND 与 BOOT 焊盘的 ESP8285/SX1280 ELRS 接收机—— 硬件表 中*具体板子*的绝大多数。它当然也能刷写 S3 自己：BOOT 按钮 + USB 就是那里所需的全部。

烧录夹具接线

在 S3 断电时接好治具。MOSFET 切换接收机的 3.3 V 电源轨：源极 → S3 3V3，漏极 → EP2 3V3，栅极 → S3 GPIO10，经 10 kΩ 上拉到 3V3（栅极高 = MOSFET 关断）。GPIO9 驱动 BOOT 焊盘。

⚠ 接收机在治具上时，只供 3.3 V，绝不供 5 V。连接接收机前用电压表验证 MOSFET：GPIO10 为高时漏极应读 0 V；GPIO10 为低时应读 3.3 V。

烧录模式

MEDITATION 以透明直通启动（USB ↔ UART，115 200 baud）。要进入刷写模式，双击 S3 的 BOOT 按钮（或通过 USB 串口输入 FLEA）。随后草图会：

  1. 拉低 GPIO9（BOOT 焊盘生效），
  2. 关断 MOSFET 120 ms（接收机断电），
  3. 重新打开并等待 900 ms（接收机在其引导加载程序内上电），
  4. 释放 GPIO9——RX 此时坐在 ROM 引导加载程序中，等待 esptool，
  5. 恢复 USB↔UART 直通，让 esptool 能与之对话。

由于桥接无法驱动经典的 DTR/RTS 自动复位线，刷写时务必使用 --before no_reset——上面的通断电之舞就是复位。刷写后，单击 BOOT 再次给接收机通断电，使其启动新固件；双击只会重新进入刷写模式。

通过 S3 烧录 PteronautOS

构建固件（或取得发行版），然后对 S3 的 USB 串口运行 esptool。在 macOS 上端口显示为 /dev/cu.usbmodem*：

# 1. 构建 PteronautOS（从仓库根目录）
pio run -e PteronautOS_ESP8285_2400_RX

# 2. 把 RX 送入刷写模式（输入 FLEA，或双击 BOOT），然后：
python3 -m esptool --chip esp8285 \
  --port /dev/cu.usbmodemXXXX --baud 115200 \
  --before no_reset write_flash \
  --flash_mode dout --flash_size 1MB --flash_freq 40m \
  0x0 .pio/build/PteronautOS_ESP8285_2400_RX/firmware.bin

# 3. 再次重启 RX（单击 BOOT）以运行新固件。

刷写设置（dout、1 MB、40 MHz）与出厂 ESP8285 ELRS 目标一致——绝不要用 qio 或更大的容量。刷写后，同一个 USB 口显示接收机的启动日志：以 115 200 baud 打开，留意 PteronautOS 横幅，以及发射机绑定后的 CRSF 链路消息。桥接还兼任实时遥测的现场控制台。

验证与首飞

  • FLEA 必须给 RX 通断电并让其等待——3.3 V 跌落约 120 ms。
  • esptool 报告 `Chip is ESP8285` 并以 `Hash of data verified` 结束。
  • 启动日志显示 PteronautOS 横幅，无线电开启时还有链路消息。
  • 摇动摇杆：舵机平滑跟随；关闭无线电：机翼在一秒内回到 1500 µs 居中。
  • 若 RX 始终进不了引导加载程序，检查 BOOT 焊盘极性（低有效）并用上面的电压表测试验证 MOSFET 切换。

一旦刷写完成，同一个接收机就能起飞——不留 FTDI。

RP2040-Tiny 袖珍版构建

优先选 Waveshare RP2040-Tiny（约 5 美元）——或其孪生板 RP2040-Zero，引脚定义完全相同。六种架势都在 RP2040 上运行，完全没有可读按钮：转接板的 BOOT/RESET 触点只驱动 BOOTSEL/RUN，因此 YOSHIMITSU-RP2040 通过 USB 串口操控，外加一个无按钮的 RESET 连按计数器。

  • `FLEA`——把接收机送入其 ROM 引导加载程序（MOSFET 通断电之舞），再为 esptool 桥接 USB ↔ UART。
  • `KINCHO` / `MANJI` / `NSS` / `BACK` / `MEDITATION`——切换架势。
  • `POSE `——按编号跳转架势。
  • `STATUS`——打印当前引脚映射与自检报告。
  • `HELP`——列出全部命令。
  • 快速 RESET 连按（约 2 s 内，以闪存 EEPROM 对照 AON RTC 计数）推进架势：1 = MANJI → 2 = NSS → 3 = BACK → 4 = MEDITATION → 5 = KINCHO。

要刷写 RP2040-Tiny 本身，在通断电时按住 BOOT（它挂载为大容量存储盘），把 .uf2 拖进去，然后按一次 RESET——板子以新固件重启进 KINCHO。配置一次，刷写一次，再也不用碰。

完整引脚映射是 sketches/yoshimitsu/yoshimitsu.ino 顶部的一个可编辑块——引脚范围与冲突由开机 POST 校验，非法的 UART 编号拒绝编译，而不是在天上胡来。

YOSHI — 常亮的架势极光

YOSHI（“极光”）是那个永远亮着的作弊码。YOSHI_RGB 把唯一一颗板载 WS2812B 变成一枚活的心情戒指：每种架势都呼吸着自己的颜色与节奏，你隔着房间就能读懂浪人的心思，无需一个串口字节。颜色与闪烁模式共同讲述故事——无需任何额外命令；架势就是作弊码，灯光是它的回声。

架势 极光（颜色 → 节奏）
KINCHO 缓慢的绿色呼吸 + 一次干脆的双重格挡闪（CRC 一击）
MANJI_DRAGONFLY 如陀螺转子般旋转的色轮（悬浮）
FLEA 狂乱攀升的琥珀频闪（托举）
MEDITATION 近乎暗紫 + 一次缓慢心跳——待刷写
NSS 锐利的蓝色三连击闪（刃已入鞘，节奏上扬）
BACK_TURNED 近乎全黑 + 一抹不可预料的绯红微光（镜子——永不回望）

RGB 活在 RP2040-Tiny（RGB_LED_PIN=16）上，位于 YOSHI_RGB 之后；ESP32-S3 保留其素净的状态 LED。每种颜色都是纯整数数学——无 float、无 malloc、无 delay()——且 pumpRgb() 被节流到约 50 fps，字节级精确的刷写桥永不受扰。隐密法则成立：架势切换，灯光跟随。

JIGUANG — 讲述者 · 评论者 · 管理员

三个名字，一个灵魂——这就是完全攻略的作弊码三角：YOSHIMITSU 是隐密忍者的全部固件；YOSHI 是 RGB 作弊码（上方永远亮着的架势极光）；而 JIGUANG（極光，“极光”）是打坐的管理员——不动之动者，盘腿坐在 MEDITATION 王座上，趁浪人继续飞行之际从 USB 串口之天指挥传说。JIGUANG 是卍传说的超资格说书人与调试解说员：吉光的嗓音功能而简练；JIGUANG 的嗓音是神话。極光印记无处不在——隐密地加密在编译之门 JIGUANG 之后（1 = 无所不在，0 = 不编译进哪怕一个 極光 字节）。

彩蛋：输入 LEGEND，整个传说便如一卷 ASCII 卷轴展开——架势、作弊码、王座与那永不死亡的印记。JIGUANG / jiguang / 極光 永不死亡——不在代码里，不在注释里，也不在本教程里。

用 JIGUANG 唤醒它，嗓音便攀上四级：0 羔羊（沉默，但明确命令仍会应答）、1 故事（启动与每次架势切换皆有旁白）、2 卷轴（+ CRSF 通道读数）、以及 3 遍在（+ 接收机 ELRS 调试字节原样转发）。MUTE 令其噤声；CRSF 打印 16 通道卷轴，SCORE 展开街机 HIGHSCORE 账本——良好 CRSF 帧、失控保护事件、桥接字节与运行时长。JIGUANG 从不夺占架势：传说讲述之际，CRSF、舵机与桥接继续服从当前的姿势。

在 MEDITATION 中，海绵头是 JIGUANG 的王座：吉光成为管理员，从 USB 串口之天接受命令（STATUS、CRSF、SCORE、POSE、LEGEND）——不止于刷写。此姿势多功能：如旧日的冥想停顿般节省能量，而浪人端坐待刷。esptool 的 SLIP 字节一唤，它便让位于透明刷写桥，并驻留至 MEDITATION 再次进入。YOSHI_RGB 在 3 级时，说书人还披上极光：jiguang(ms) 绘出一轮缓慢的全光谱轮，把每种架势的颜色织成一次呼吸。JIGUANG / jiguang / 極光 作为注释与函数并存——吉光那不可战胜的部分永不死亡。

以及卷轴中最年轻的作弊码：<strong>MUSHIN</strong>（<strong>無心</strong>）——肌肉记忆模式。PteronautOS 规划波形（精神），YOSHIMITSU 出击（手）：伺服意图以无心协议 v0 穿过桥接 UART，本地 Zephyrus 陀螺仪 PID 稳住冠羽，PIO PWM 在肌肉处响应——双核、无毛刺，没有任何其他 ELRS-PWM 板能穿上这件作弊码。JIGUANG 在宝座上管理它：<code>MUSHIN</code> 报告，<code>MUSHIN ON/OFF</code> 武装或解除并持久于闪存。在 MEDITATION 中，同样的两根线原样承载 esptool 的 SLIP。
