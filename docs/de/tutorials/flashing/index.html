PTERONAUTOS Tutorials Hardware Dokumentation

Tutorial 01

PteronautOS flashen

Bauen und installieren Sie die hermetische Firmware am Beispiel eines CYCLONE ELRS 2,4-GHz-7CH-PWM-RX-Empfängers.

PteronautOS unterstützt auch andere Empfängerplatinen. Ein gemeinsamer ESP8285 macht die Verdrahtung nicht identisch: exponierte GPIOs, Kanalzuordnung, Programmieranschlüsse und PCB-Revisionen können abweichen. Die unten gezeigte Spannungs- und CH2/CH3-Verdrahtung gilt für dieses CYCLONE-Beispiel; prüfen Sie das Pinout Ihrer Platine und die unterstützte Hardwarekonfiguration, bevor Sie einen anderen Empfänger anschließen.

Entfernen Sie vor dem Anschließen der Spannung die Antriebslasten vom Flügelmechanismus und stellen Sie sicher, dass kein Servo gegen einen harten Anschlag fahren kann. Flashen ist elektrische Arbeit; die Zelle muss während des gesamten Verfahrens mechanisch sicher bleiben.

01 · Firmware bauen

Klonen Sie das Repository, installieren Sie PlatformIO und führen Sie den folgenden Befehl im Repository-Root aus. Das PlatformIO-Projekt liegt in src; dieser Befehl baut die dedizierte ESP8285-Empfängerumgebung dieses Beispiels.

pio run -d src -e PteronautOS_ESP8285_2400_RX

02 · Empfänger anschließen

Verwenden Sie für diesen CYCLONE-Empfänger den 5-V-Ausgang des FTDI-Adapters für die Empfängerversorgung, nicht dessen 3,3-V-Ausgang. Seine UART-Verbindungen liegen auf den Signalpins von Kanal 2 und 3 — separate UART-Pads müssen nicht gesucht werden.

FTDI-Adapter Empfängeranschluss
GND GND (−)
5 V / VCC Versorgung (+)
TX CH3-Signal — Empfänger-RX (GPIO3)
RX CH2-Signal — Empfänger-TX (GPIO1)

Die 5-V-Einstellung bezieht sich auf die Empfängerversorgung. Prüfen Sie die Dokumentation Ihres Adapters: TX/RX müssen ESP8285-kompatible 3,3-V-Logik verwenden, auch wenn die Versorgung 5 V liefert. Schließen Sie nicht gleichzeitig eine zweite Spannungsversorgung an.

03 · Bootloader aufrufen

Halten Sie BOOT (GPIO0) gedrückt, ziehen Sie das FTDI-USB-Kabel ab und stecken Sie es wieder ein, halten Sie BOOT etwa eine Sekunde lang gedrückt und lassen Sie es dann los. Das Flash-Skript führt keinen automatischen Reset durch — rufen Sie den Bootloader daher manuell auf, bevor Sie es ausführen.

04 · Image schreiben

Führen Sie im Repository-Root das bereitgestellte Flash-Skript aus. Es sucht ein funktionierendes, von PlatformIO gebündeltes Flash-Werkzeug und die gebaute Firmware, wählt einen seriellen Port und schreibt das Image mit den erforderlichen Flash-Einstellungen.

./scripts/flash.sh

Die automatische Portauswahl sucht nach macOS-Geräten unter /dev/cu.*. Wenn mehrere serielle Geräte angeschlossen sind oder Sie ein anderes Betriebssystem nutzen, wählen Sie den Port des Empfängeradapters explizit aus. Ersetzen Sie das Beispiel unten durch Ihren tatsächlichen Gerätepfad.

./scripts/flash.sh --port /dev/cu.usbserial-XXXX

Um die Bootloader-Kommunikation ohne Firmware-Schreiben zu prüfen, nutzen Sie den optionalen Prüfmodus. Schlägt er fehl, wiederholen Sie den BOOT-Stromzyklus, bevor Sie es erneut versuchen.

./scripts/flash.sh --port /dev/cu.usbserial-XXXX --check

05 · Installation prüfen

Starten Sie den Empfänger neu, ohne BOOT zu halten. Bestätigen Sie, dass sein WiFi-Zugangspunkt und die WebUI verfügbar werden (SSID: Pteronaut OS , Passwort: flynatural ), laden Sie dann die Konfiguration und prüfen Sie den Target-Namen, bevor Sie die Servos wieder anschließen.

Fahren Sie fort mit der Hardware-Seite für Pinbelegungen und revisionsspezifische Verdrahtungshinweise.
