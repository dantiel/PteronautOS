YOSHIMITSU — 完全ソリューション：すべてのチートコード、ひとつの巻物

ひとつのスケッチ、ふたつのボード、六つの構え。YOSHIMITSUは完全なヘルメティック・ソリューション — CRSF→PWMコンバーター(KINCHO)、Zephyrusジャイロ浮揚(MANJI_DRAGONFLY)、EP2ポケットフラッシャー(FLEA · MEDITATION)、刀なしのベンチ(NSS)、振り返らない鏡(BACK_TURNED) — そしてYOSHIオーロラと、すべてを語る瞑想の管理者JIGUANG。

1枚のボード、6つの構え

YOSHIMITSUは六つの構えを持つ隠密の忍（Hermetic Shinobi）——道具は二つではなく、魂は一つ。ひとつのスケッチが両ボードをビルドし、構えはUSBコマンド、GPIO0ボタン（ESP32-S3）、またはRESETタップ（RP2040-Tiny）で切り替わります：

構え 意味
KINCHO CRSF→PWMコンバータ——受け流し（CRCが偽りを捨てる）。チャンネル名なし、ジャイロなし。
MANJI_DRAGONFLY コンバータ＋Zephyrusジャイロリンク（MPU6050は任意）——浮揚。
FLEA 電源サイクル治具——RXをブートローダーへ落とす持ち上げ。
MEDITATION ポケットフラッシャー——海綿頭、エネルギーを蓄え、書き込みに備える。
NSS 無刀の作業台——USB直結サーボ、RFなし。
BACK_TURNED 欺きの静寂——生きたUARTの鏡。決して振り返らない。

スケッチひとつ、対象ふたつ：sketches/yoshimitsu/yoshimitsu.ino はWaveshare RP2040-Tiny（最軽量、オンボードボタンなし）およびネイティブUSBのESP32-S3向けに、標準のarduino-pico / arduino-esp32コアでコンパイルされます。

YOSHIMITSU — 統合ファームウェア

YOSHIMITSUは推奨ファームウェアです。KINCHO（コンバータ）で起動し、構えの間を移動します。USBコンソールは両ボードで正統のスイッチ——KINCHO → MANJI → FLEA → MEDITATION → NSS → BACK → POSE <n>。ESP32-S3ではBOOTボタン（GPIO0）が第二の表面です：

文脈 所作 動作
どの構えでも ダブルタップ KINCHO → MANJI → NSS → BACK → KINCHO → と巡回
どの構えでも 2秒長押し MEDITATIONへ入る
MEDITATION / FLEA シングルタップ 受信機を再起動（新しいファームウェアを実行）
MEDITATION / FLEA ダブルタップ FLEA——受信機をブートローダーへ落とす

配線はひとつの恒久ハーネス——同じ線がすべての構えに仕えるので、飛行と書き込みの間で配線し直すことは二度とありません。MEDITATIONではUSB→UART経路は純粋な透過ブリッジ（行解析なし）なので、esptoolのバイナリSLIP通信は無傷で通り抜けます。全ソース：sketches/yoshimitsu/yoshimitsu.ino（設定の殻）とsrc/Yoshimitsu.h（ライブラリの核）。

ライブラリ・ドングル — 設定に再び触れずに更新

YOSHIMITSUはグラリャ・アズール戦略に従います：フォルダ全体がライブラリ・ドングルです。スケッチsketches/yoshimitsu/yoshimitsu.inoは薄い設定の殻（ピン、フラグ、BOARD_CUSTOMブロック）にすぎず、隠密の忍の全体はsrc/Yoshimitsu.hに、すべての既定はsrc/Yoshimitsu_Padraos.h（パドロインス）に生きています。ドングルの更新：ライブラリフォルダでgit pull——または新しいリリースを置く——だけで、設定スケッチは無傷のままです。一度Arduinoライブラリとしてインストールすれば（librariesフォルダへシンボリックリンクかコピー）、ファームウェア更新は決して再配線でも再設定でもありません。

  • `src/Yoshimitsu.h` — 核の全体：構え、CRSF、MUSHIN、JIGUANG、フラッシャーブリッジ。
  • `src/Yoshimitsu_Padraos.h` — すべての既定（ピン、タイミング、ゲートレベル）を`*_PADRAO`値として。
  • `library.properties` — Arduinoライブラリのマニフェスト（バージョン、アーキテクチャ）。
  • `yoshimitsu.ino` — 設定のみ；includeの前に定義して何でも上書き。

KINCHO — CRSF→PWM 変換器

KINCHO——コンバータの構え——はUARTでCRSFを420 000 baudで読み、172–1811のチャンネル範囲から写像した988–2012 µsの窓でサーボを駆動し、500 msのフェイルセーフで中央に揃えます。受け流しとはCRC検査のこと：壊れたフレームはサーボに届く前に捨てられます。コンバータはチャンネルに無頓着です——サーボはSERVO_PIN_1..8、CHANNEL_TO_SERVO表が各サーボへ供給するCRSFチャンネルを決め、チャンネルの意味はミキサー／カーネルのもので、ボードのものでは決してありません。

  • ESP32-S3：RX TX → GPIO44、RX RX → GPIO43、共通GND、共有5 Vレール。
  • RP2040-Tiny：RX TX → GPIO1（UART0）、共通GND。
  • サーボ：`SERVO_PIN_1..3`（S3ではさらに3つ）——PIN MAPブロックで上書き可能。

ジャイロ安定オーニソプターにはMANJI_DRAGONFLYを使います——同じコンバータにZephyrusリンクを加えたもの：GYRO_SDA/GYRO_SCL上の任意のMPU6050がヨーレート補正を冠羽サーボへ送ります。ジャイロ未配線なら、MANJI_DRAGONFLYは優雅にKINCHOへ退行します。市販のCRSF→PWMコンバータ基板にはジャイロ経路がまったくありません——EP2級受信機はIMUを積まないので、Zephyrusは受信機ではなくYOSHIMITSUの中に生きています。

受信機がすでにPWMを話すなら（5 chまたは7 ch基板）、コンバータの構えは一切不要です——その場合、下のMEDITATIONがS3を所有する唯一の理由になります。

KINCHOI — EP2級レシーバー用ポケットフラッシャー

問題：EP2級受信機（HappyModel EP2、EP1、EPW6、…）はキャスタレーション・パッドにCRSFを出し、極小のBOOTパッドを載せています。FTDIアダプタを使うということは、受信機の電源を入れ直す間、1 mmのパッド二つにプローブを当て続けるということ——扱いにくく、ファームウェア更新のたびに再はんだか再クリップが必要です。

解決策：ESP32-S3をフラッシャーにしましょう。GPIO一本が受信機のBOOTパッドをLOWに保持し、小さなP-MOSFETがソフトウェア制御で受信機の3.3 Vレールを切り替え、USBポートがシリアルポートになります。S3のボタンを一度押せば、ESP8285をROMブートローダーへ落とす正確な電源サイクルの舞いを演じ——その後esptoolがブリッジをまっすぐ通って書き込みます。FTDIなし、プローブなし、繰り返しのはんだ付けなし：受信機のパッドを一度だけ短いピグテールにはんだ付けして、永遠に使い回せます。

ブリッジは、TX、RX、3V3、GND、BOOTパッドを露出するすべてのESP8285/SX1280 ELRS受信機で動きます—— ハードウェア表 にある*具体的な基板*の圧倒的多数です。もちろんS3自体もフラッシュします：BOOTボタン＋USB、それがそこに必要なすべてです。

書き込みジグの配線

フラッシュモード

MEDITATIONは透過パススルー（USB ↔ UART、115 200 baud）で起動します。フラッシュモードに入るには、S3のBOOTボタンをダブルタップします（またはUSBシリアルでFLEAと入力）。するとスケッチは：

  1. GPIO9をLOWに引き（BOOTパッド有効）、
  2. MOSFETを120 msオフにし（受信機の電源断）、
  3. 再びオンにして900 ms待ち（受信機がブートローダー内で起動）、
  4. GPIO9を解放——RXはROMブートローダーに座してesptoolを待つ、
  5. USB↔UARTパススルーを再開し、esptoolが対話できるようにする。

ブリッジは古典的なDTR/RTS自動リセット線を駆動できないため、必ず--before no_resetでフラッシュしてください——上の電源サイクルの舞いこそがリセットです。フラッシュ後、シングルのBOOTタップで受信機の電源が再び巡り、新しいファームウェアが起動します；ダブルタップは単にフラッシュモードへ再入するだけです。

S3経由でPteronautOSを書き込む

ファームウェアをビルドし（またはリリースを取得し）、S3のUSBシリアルポートへesptoolを実行します。macOSではポートは/dev/cu.usbmodem*と表示されます：

# 1. PteronautOSをビルド（リポジトリルートから）
pio run -e PteronautOS_ESP8285_2400_RX

# 2. RXをフラッシュモードへ落とす（FLEA入力、またはBOOTダブルタップ）、その後：
python3 -m esptool --chip esp8285 \
  --port /dev/cu.usbmodemXXXX --baud 115200 \
  --before no_reset write_flash \
  --flash_mode dout --flash_size 1MB --flash_freq 40m \
  0x0 .pio/build/PteronautOS_ESP8285_2400_RX/firmware.bin

# 3. RXをもう一度再起動（シングルBOOTタップ）して新ファームウェアを実行。

フラッシュ設定（dout、1 MB、40 MHz）は純正ESP8285 ELRSターゲットと一致します——qioやより大きなサイズは決して使わないでください。フラッシュ後、同じUSBポートが受信機のブートログを表示します：115 200 baudで開き、PteronautOSバナーと、送信機がバインドしたらCRSFリンクアップメッセージを確認してください。ブリッジはライブテレメトリのフィールドコンソールも兼ねます。

確認と初飛行

  • FLEAはRXの電源を巡らせて待機させねばなりません——3.3 Vが約120 ms落ち込みます。
  • esptoolが`Chip is ESP8285`を報告し、`Hash of data verified`で終わります。
  • ブートログにPteronautOSバナーと、無線オンならリンクアップメッセージが出ます。
  • スティックを揺らす：サーボは滑らかに追従します；無線を切ると：翼は1秒以内に1500 µsへ中央に戻ります。
  • RXが一向にブートローダーへ入らない場合は、BOOTパッドの極性（アクティブロー）と、上の電圧計テストでMOSFETの切替を確認してください。

一度フラッシュすれば、同じ受信機が飛びます——FTDIは残りません。

RP2040-Tiny ポケットビルド

Waveshare RP2040-Tiny（約5 USD）を選びましょう——または、まったく同じピン配置を共有する双子のRP2040-Zeroを。六つの構えはすべてRP2040上で読み取り可能なボタンなしに動きます：アダプタのBOOT/RESETタップはBOOTSEL/RUNのみを駆動するので、YOSHIMITSU-RP2040はUSBシリアルポートと、ボタンなしのRESETタップ計数器で操られます。

  • `FLEA` — 受信機をROMブートローダーへ落とし（MOSFET電源サイクルの舞い）、esptoolのためにUSB ↔ UARTを橋渡し。
  • `KINCHO` / `MANJI` / `NSS` / `BACK` / `MEDITATION` — 構えを切替。
  • `POSE ` — 番号で構えへ跳ぶ。
  • `STATUS` — 有効なピンマップと自己診断報告を印字。
  • `HELP` — 全コマンドを列挙。
  • 素早いRESETタップ（約2 s以内、AON RTCに対するフラッシュEEPROMで計数）が構えを進めます：1 = MANJI → 2 = NSS → 3 = BACK → 4 = MEDITATION → 5 = KINCHO。

RP2040-Tiny自体をフラッシュするには、電源循環中にBOOTを押し（大容量ストレージとしてマウントされる）、.uf2を置き、RESETを一度押します——ボードは新ファームウェアでKINCHOへ再起動します。一度設定、一度フラッシュ、二度と触れない。

YOSHI — 常時点灯の構えオーロラ

YOSHI（「オーロラ」）は常時点灯のチートコードです。YOSHI_RGBが唯一のオンボードWS2812Bを生きたムードリングに変えます：構えごとに自らの色と律動で呼吸するので、シリアル1バイトもなく部屋の向こうから浪人の心が読めます。色と点滅パターンが物語を語ります——追加コマンドは不要；構えこそがチートコード、光はそのこだまです。

構え オーロラ（色 → 律動）
KINCHO ゆっくりとした緑の呼吸＋鮮やかな二重の受け流しフラッシュ（CRCの一撃）
MANJI_DRAGONFLY ジャイロの回転子のように回る色相環（浮揚）
FLEA 狂おしく立ち上がる琥珀のストロボ（持ち上げ）
MEDITATION ほぼ暗い菫＋ゆっくりした心拍ひとつ——書き込みに備える
NSS 青の鋭い三連タップフラッシュ（刃は鞘に、テンポは上へ）
BACK_TURNED ほぼ黒＋予測不能な深紅の煌めきひとつ（鏡——決して振り返らない）

RGBはRP2040-Tiny（RGB_LED_PIN=16）にYOSHI_RGBの奥で生きています；ESP32-S3は質素な状態LEDを保ちます。すべての色は純粋な整数演算——floatなし、mallocなし、delay()なし——そしてpumpRgb()は約50 fpsに絞られ、バイト厳密なフラッシャーブリッジが乱されることは決してありません。隠密の掟は保たれます：構えが変われば、光が従う。

JIGUANG — 語り部 · 解説者 · 管理者

三つの名、一つの魂——これが完全攻略のチートコード三角形です：YOSHIMITSUは隠密の忍のファームウェア全体；YOSHIはRGBチートコード（上記の常時点灯の構えオーロラ）；そしてJIGUANG（極光、「オーロラ」）は瞑想する管理者——MEDITATIONの玉座に胡坐をかき、浪人が飛び続けるあいだUSBシリアルの天から伝説を指揮する不動の動者です。JIGUANGは卍伝説の過剰資格の語り部でありデバッグ解説者：ヨシミツの声は機能的で簡潔、JIGUANGの声は神話です。極光の印はどこにでも書かれています——コンパイルの門JIGUANGの奥に隠密的に暗号化され（1＝遍在、0＝極光の1バイトすらコンパイルされない）。

イースターエッグ：LEGENDと入力すれば、伝説全体がひとつのASCII巻物として展開します——構え、チートコード、玉座、そして決して死なない印。JIGUANG / jiguang / 極光は決して死にません——コードでも、コメントでも、このチュートリアルでも。

JIGUANGで目覚めさせると、声は四段階を登ります：0 子羊（沈黙、ただし明示コマンドには応答）、1 物語（起動とすべての構え替えを語る）、2 巻物（＋CRSFチャンネル読み出し）、そして3 遍在（＋受信機のELRSデバッグバイトをそのまま通過）。MUTEが黙らせます；CRSFは16チャンネルの巻物を印字し、SCOREはアーケードのHIGHSCORE台帳を展開します——良好なCRSFフレーム、フェイルセーフ事象、ブリッジバイト、稼働時間。JIGUANGは決して構えを奪いません：伝説が語られる間も、CRSF、サーボ、ブリッジは姿勢に従い続けます。

MEDITATIONでは海綿頭がJIGUANGの玉座です：ヨシミツは管理者となり、USBシリアルの天から命令を受けます（STATUS、CRSF、SCORE、POSE、LEGEND）——ただ書き込む以上の存在。この構えは多機能です：古い瞑想の一時停止のようにエネルギーを蓄え、浪人は書き込まれる用意をして座しています。esptoolのSLIPバイトが呼んだ瞬間、透過フラッシャーブリッジへ譲り、MEDITATIONが再び入るまでそこに留まります。YOSHI_RGBがレベル 3なら語り部はオーロラを纏いもします：jiguang(ms)が、すべての構えの色をひとつの呼吸に織る、ゆっくりした全スペクトルの車輪を描きます。JIGUANG / jiguang / 極光はコメントとしても関数としても残ります——ヨシミツの不敗の部分は決して死にません。

そして巻物の最年少チートコード: MUSHIN(無心)——筋肉記憶モード。PteronautOS が波を計画し(精神)、YOSHIMITSU が打つ(手): サーボ・インテントが無心プロトコル v0 としてブリッジ UART を渡り、ローカルの Zephyrus ジャイロ PID が鶏冠を支え、PIO PWM が筋肉で応える——デュアルコア、グリッチなし、他のどの ELRS-PWM ボードも着られないチートコード。JIGUANG が玉座から管理する: MUSHIN は報告し、MUSHIN ON/OFF は武装・解除してフラッシュに残す。MEDITATION では同じ二本の線が esptool の SLIP をそのまま運ぶ。
