チュートリアル 01

PteronautOS の書き込み

CYCLONE ELRS 2.4GHz 7CH PWM RX レシーバーを例に、ハーメティック・ファームウェアをビルドして書き込みます。

PteronautOS は他の受信機ボードもサポートします。ESP8285 を共有していても配線が同一とは限りません: 露出した GPIO、チャンネル割り当て、書き込み用接続、PCB リビジョンは異なる場合があります。以下の電源と CH2/CH3 の配線はこの CYCLONE の例に適用されます。別の受信機を接続する前に、ボードのピン配置とサポートされるハードウェア構成を確認してください。

電源を接続する前に、翼機構から推進負荷を取り除き、どのサーボも硬いストッパーに当たらないことを確認してください。書き込みは電気的な作業です。手順の間、機体は機械的に安全な状態を保つ必要があります。

01 · ファームウェアをビルド

リポジトリをクローンし、PlatformIO をインストールして、リポジトリのルートから次のコマンドを実行します。PlatformIO プロジェクトは src にあります。このコマンドは、この例で使う専用の ESP8285 受信機環境をビルドします。

pio run -d src -e PteronautOS_ESP8285_2400_RX

02 · 受信機を接続

この CYCLONE 受信機では、受信機の電源に FTDI アダプタの 5V 出力を使い、3.3V 出力は使わないでください。UART 接続はチャンネル 2 と 3 の信号ピンにあり、別途 UART パッドを探す必要はありません。

FTDI アダプタ 受信機の接続
GND GND (−)
5 V / VCC 電源 (+)
TX CH3 信号 — 受信機 RX (GPIO3)
RX CH2 信号 — 受信機 TX (GPIO1)

5V 設定は受信機の電源を指します。アダプタのドキュメントを確認してください: 供給出力が 5V でも、TX/RX は ESP8285 互換の 3.3V ロジックを使う必要があります。同時に 2 つ目の電源を接続しないでください。

03 · ブートローダーに入る

BOOT（GPIO0）を押したまま FTDI の USB ケーブルを抜き差しし、BOOT を約 1 秒押し続けてから離します。書き込みスクリプトは自動リセットを行わないため、実行前に手動でブートローダーに入ってください。

04 · イメージを書き込む

リポジトリのルートから、提供された書き込みスクリプトを実行します。スクリプトは PlatformIO 同梱の書き込みツールとビルド済みファームウェアを探し、シリアルポートを選び、必要なフラッシュ設定でイメージを書き込みます。

./scripts/flash.sh

自動ポート選択は macOS の /dev/cu.* デバイスを探します。複数のシリアルデバイスが接続されている場合や、別の OS を使っている場合は、受信機アダプタのポートを明示的に選択してください。下の例を実際のデバイスパスに置き換えてください。

./scripts/flash.sh --port /dev/cu.usbserial-XXXX

ファームウェアを書き込まずにブートローダー通信を確認するには、オプションのチェックモードを使います。失敗したら、再試行する前に BOOT の電源サイクルを繰り返してください。

./scripts/flash.sh --port /dev/cu.usbserial-XXXX --check

05 · インストールを確認

BOOT を押さずに受信機の電源を入れ直します。WiFi アクセスポイントと WebUI が利用可能になったことを確認してください（SSID: Pteronaut OS 、パスワード： flynatural ）、その後設定を読み込み、サーボを再接続する前にターゲット名を確認してください。

続いて ハードウェアページ でピン配置とリビジョン固有の配線ノートを確認できます。
