ESP32-S3 ツールボックス

約6USDのESP32-S3を2つの道具に：微動だにしないCRSF→PWMサーボ変換器と、はんだ付けFTDIなしでEP2級レシーバーにPteronautOSを書き込めるポケットフラッシャー。

1枚のボード、2つの道具

Both personalities run on the same hardware — a Waveshare-style ESP32-S3 micro board (~6 USD, 23 × 18 mm, native USB, every GPIO PWM-capable). The two faces now live in one combined sketch — HERMES, with the two standalone sketches still available if you want only one tool:

Tool Sketch Turns the S3 into… Used for
HERMES (combined) esp32s3_hermes Both faces in one — converter and flasher, GPIO0 double-tap to switch One permanent harness for flying and flashing
A — Converter esp32s3_crsf_pwm A rock-steady CRSF→PWM servo driver (up to 8 channels) Driving wing + rudder servos from any CRSF-only receiver
B — Pocket flasher esp32s3_flash_bridge A USB↔UART bridge with a boot + power-cycle jig Flashing PteronautOS onto EP2-class receivers — no soldered FTDI

All three sketches live in the repository under sketches/esp32s3_hermes/, sketches/esp32s3_crsf_pwm/ and sketches/esp32s3_flash_bridge/ and compile with the standard arduino-esp32 core.

HERMES — 統合ファームウェア

HERMES — the Hermetic Shinobi — is the recommended firmware: one board, two faces. It boots in FACE I (converter) and switches to FACE II (flasher) with a GPIO0 double-tap. The BOOT button is the single control surface:

Face Gesture Action
FACE I (converter) double-tap enter FACE II (flasher)
FACE II (flasher) single tap restart the receiver (run the new firmware)
FACE II (flasher) double-tap drop the receiver into its bootloader (flash mode)
FACE II (flasher) long-press 2 s return to FACE I (converter)

The wiring is one permanent harness — the same six wires serve both faces, so you never re-wire between flying and flashing. In FACE II the USB↔UART path is a pure transparent bridge (no line parsing), so esptool's binary SLIP traffic passes through untouched. Full source: sketches/esp32s3_hermes/esp32s3_hermes.ino.

A — CRSF→PWM 変換器（復習）

Flashing the converter sketch follows the exact procedure described in Tutorial 06 — CRSF→PWM Converter: CRSF at 420 000 baud on the UART, servos on three free GPIOs, a 988–2012 µs window mapped from the 172–1811 channel range, and a failsafe that centres the servos when no valid frame arrives for 500 ms.

  • Wiring recap: RX TX → S3 GPIO44, RX RX → S3 GPIO43, common GND, shared 5 V rail.
  • Servos: GPIO1 (left wing), GPIO2 (right wing), GPIO3 (crest rudder) — all overrideable in the sketch.
  • Full, CRC-checked source: sketches/esp32s3_crsf_pwm/esp32s3_crsf_pwm.ino

If your receiver already speaks PWM (a 5 ch or 7 ch board), you do not need personality A at all — the pocket flasher below is then your only reason to own the S3.

B — EP2級レシーバー用ポケットフラッシャー

The problem: EP2-class receivers (HappyModel EP2, EP1, EPW6, …) expose CRSF on castellated pads and carry a tiny BOOT pad. Using an FTDI adapter means holding a probe against two 1 mm pads while power-cycling the receiver — awkward, and you re-solder or re-clip every time the firmware needs an update.

The solution: let the ESP32-S3 be the flasher. One GPIO holds the receiver's BOOT pad low; a small P-MOSFET switches the receiver's 3.3 V rail under software control; the USB port becomes the serial port. Press one button on the S3 and it performs the exact power-cycle dance that drops an ESP8285 into its ROM bootloader — then esptool writes straight through the bridge. No FTDI, no probes, no repeated soldering: solder the receiver's pads once to a short pigtail and reuse it forever.

Parts list:

Part Typical part number Cost

The bridge works with every ESP8285/SX1280 ELRS receiver that exposes TX, RX, 3V3, GND and a BOOT pad — the overwhelming majority of the concrete boards in the hardware table. It also flashes the S3 itself, of course: BOOT button + USB is all that needs there.

書き込みジグの配線

Wire the jig with the S3 unpowered. The MOSFET switches the receiver's 3.3 V rail: source ← S3 3V3, drain → EP2 3V3, gate ← S3 GPIO10 with a 10 kΩ pull-up to 3V3 (gate high = MOSFET off). GPIO9 drives the BOOT pad.

TX (CRSF out) GPIO18 (U1RX) RX ← TX (cross)
RX (CRSF in) GPIO17 (U1TX) TX → RX (cross)
GND GND Common ground (mandatory)

S3 GPIO10 ──► gate         (10kΩ pull-up to 3V3; LOW = ON)

Power polarity & voltage — feed the receiver 3.3 V only, never 5 V, while it is on the jig. Verify the MOSFET with a voltmeter before connecting a receiver: with GPIO10 HIGH the drain must read 0 V; with GPIO10 LOW it must read 3.3 V.

ブリッジスケッチのフラッシュモード

The bridge sketch boots into transparent passthrough (USB ↔ UART at 115 200 baud). To enter flash mode, press the S3's BOOT button twice within one second — or send the line FLASH over the USB serial. The sketch then:

  1. pulls GPIO9 low (BOOT pad asserted),
  2. switches the MOSFET off for 120 ms (receiver power off),
  3. switches it back on and waits 800 ms (receiver powers up inside its bootloader),
  4. releases GPIO9 — the RX now sits in the ROM bootloader, waiting for esptool,
  5. resumes USB↔UART passthrough so esptool can talk to it.

Because the bridge cannot drive the classic DTR/RTS auto-reset lines, always flash with --before no_reset — the power-cycle dance above is the reset. After flashing, a single BOOT press power-cycles the receiver again so it boots the new firmware; two presses within the window would merely re-enter flash mode.

S3経由でPteronautOSを書き込む

Build the firmware (or fetch a release), then run esptool against the S3's USB serial port. On macOS the port shows up as /dev/cu.usbmodem*: 

# 1. Build PteronautOS (from the repository root)
pio run -e PteronautOS_ESP8285_2400_RX

# 2. Drop the RX into flash mode via the S3 (BOOT twice), then:
python3 -m esptool --chip esp8285 \
  --port /dev/cu.usbmodemXXXX --baud 115200 \
  --before no_reset write_flash \
  --flash_mode dout --flash_size 1MB --flash_freq 40m \
  0x0 .pio/build/PteronautOS_ESP8285_2400_RX/firmware.bin

# 3. Restart the RX once more (single BOOT press) to run the new firmware.

The flash settings (dout, 1 MB, 40 MHz) match the stock ESP8285 ELRS target — never use qio or a larger size. After flashing, the very same USB port shows the receiver's boot log: open it at 115 200 baud and watch for the PteronautOS banner and, once a transmitter binds, the CRSF link-up messages. The bridge doubles as your field console for live telemetry.

確認と初飛行

  • Flash mode: BOOT twice must power-cycle the RX and leave it waiting — the 3.3 V dips for ~120 ms.
  • esptool reports Chip is ESP8285 and finishes with Hash of data verified.
  • The boot log shows the PteronautOS banner and, with the radio on, a link-up message.
  • Wiggle the sticks: servos track smoothly; switch the radio off: wings centre to 1500 µs within a second.
  • If the RX never enters the bootloader, check the BOOT-pad polarity (active low) and the MOSFET switching with the voltmeter test above.

Once flashed, the same receiver flies — no FTDI left behind.
