PTERONAUTOS Tutoriels Matériel Documentation

Tutoriel 01

Flasher PteronautOS

Compilez et installez le firmware hermétique en utilisant un récepteur CYCLONE ELRS 2,4 GHz 7CH PWM RX comme exemple.

PteronautOS prend aussi en charge d'autres cartes réceptrices. Partager un ESP8285 ne rend pas leur câblage identique : les GPIO exposés, l'affectation des canaux, les connexions de programmation et les révisions de PCB peuvent différer. L'alimentation et le câblage CH2/CH3 ci-dessous s'appliquent à cet exemple CYCLONE ; vérifiez le brochage de votre carte et la configuration matérielle prise en charge avant de connecter un autre récepteur.

Avant de brancher l'alimentation, retirez les charges propulsives du mécanisme d'aile et assurez-vous qu'aucun servo ne puisse atteindre une butée dure. Le flashage est un travail électrique ; la cellule doit rester mécaniquement sûre pendant toute la procédure.

01 · Compiler le firmware

Clonez le dépôt, installez PlatformIO et exécutez la commande suivante depuis la racine du dépôt. Le projet PlatformIO est dans src ; cette commande compile l'environnement dédié du récepteur ESP8285 utilisé dans cet exemple.

pio run -d src -e PteronautOS_ESP8285_2400_RX

02 · Connecter le récepteur

Pour ce récepteur CYCLONE, utilisez la sortie 5 V de l'adaptateur FTDI pour l'alimentation du récepteur, pas sa sortie 3,3 V. Ses connexions UART sont sur les broches de signal des canaux 2 et 3 — nul besoin de repérer des pastilles UART séparées.

Adaptateur FTDI Connexion du récepteur
GND GND (−)
5 V / VCC Alimentation (+)
TX Signal CH3 — RX du récepteur (GPIO3)
RX Signal CH2 — TX du récepteur (GPIO1)

Le réglage 5 V concerne l'alimentation du récepteur. Consultez la documentation de votre adaptateur : TX/RX doivent utiliser une logique 3,3 V compatible ESP8285, même lorsque la sortie d'alimentation est de 5 V. Ne branchez pas une seconde alimentation en même temps.

03 · Entrer dans le bootloader

Maintenez BOOT (GPIO0) enfoncé, débranchez et rebranchez le câble USB du FTDI, gardez BOOT enfoncé environ une seconde puis relâchez-le. Le script de flashage n'effectue pas de réinitialisation automatique : entrez donc dans le bootloader manuellement avant de l'exécuter.

04 · Écrire l'image

Depuis la racine du dépôt, exécutez le script de flashage fourni. Il localise un outil de flashage fourni avec PlatformIO et le firmware compilé, sélectionne un port série et écrit l'image avec les réglages flash requis.

./scripts/flash.sh

La sélection automatique du port recherche les périphériques macOS /dev/cu.*. Si plusieurs périphériques série sont connectés, ou si vous utilisez un autre système d'exploitation, sélectionnez explicitement le port de l'adaptateur du récepteur. Remplacez l'exemple ci-dessous par le chemin réel de votre périphérique.

./scripts/flash.sh --port /dev/cu.usbserial-XXXX

Pour vérifier la communication avec le bootloader sans écrire le firmware, utilisez le mode de vérification optionnel. En cas d'échec, répétez le cycle d'alimentation de BOOT avant de réessayer.

./scripts/flash.sh --port /dev/cu.usbserial-XXXX --check

05 · Vérifier l'installation

Redémarrez le récepteur sans maintenir BOOT. Confirmez que son point d'accès WiFi et sa WebUI deviennent disponibles (SSID : Pteronaut OS , mot de passe : flynatural ), puis chargez la configuration et vérifiez le nom de la cible avant de reconnecter les servos.

Poursuivez avec la page Matériel pour les brochages et les notes de câblage spécifiques à la révision.
