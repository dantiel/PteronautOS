PTERONAUTOS Tutoriais Hardware Documentação

Developer 01

Desenvolver o PteronautOS

Compile, configure e estenda o firmware hermético. Este guia assume que está à vontade na linha de comandos.

O PteronautOS é um fork do ExpressLRS 4.x transformado em controlador de voo para ornitópteros a servos, a correr no ESP8285 @ 80 MHz / 1 MB flash.

Se só quer um build local para flashear, salte para o guia do flash.sh — ele resume tudo o que se segue num só comando.

1 · Pré-requisitos da toolchain

Siga primeiro o guia de instalação da toolchain do ExpressLRS — é a configuração oficial para a toolchain exata de PlatformIO + ESP8266 que este fork usa.

Requisito Notas
PlatformIO Core `pio` no PATH — descarrega a toolchain ESP8266/Arduino no primeiro build
Node.js `20.x` (`.nvmrc` fixa 20.20.2) — use `nvm use 20`
Git para clonar o repositório
Python 3 para o verificador de imagem e os scripts de build

Se já tem o PlatformIO instalado, verifique:

pio --version
node --version   # should print v20.x

Não salte o passo da toolchain do ExpressLRS — os pré-requisitos de máquina (Python, drivers série/udev, PATH) vêm desse guia.

Configuração no Windows (sem VS Code)

No Windows não precisa do VS Code — tudo corre pela consola. Cole isto uma vez no PowerShell (ou Windows Terminal):

winget install --id Git.Git -e
winget install --id OpenJS.NodeJS.LTS -e
winget install --id Python.Python.3.12 -e
python -m pip install -U platformio

Depois abra o Git Bash (instalado com o Git) e execute todos os comandos a partir daí — git, pio, npm e ./scripts/flash.sh funcionam sem alterações. No Windows, salte o nvm use 20: o Node 20 já está no PATH, por isso execute apenas npm run build:pteronautos diretamente.

Sem winget? Instale o Git, o Node.js 20 e o Python a partir das páginas oficiais de download e depois execute a linha do PlatformIO acima.

2 · Obter o código

git clone https://github.com/dantiel/PteronautOS.git
cd PteronautOS

O projeto é um projeto PlatformIO autocontido na pasta `src/`, sem bibliotecas de terceiros fora do `lib_deps` dos targets.

3 · Estrutura do repositório

Caminho Função
src/platformio.ini Raiz PlatformIO — lista os ficheiros .ini dos targets
src/targets/pteronautos-rx.ini Definições de target do PteronautOS (os envs que compila)
src/targets/common.ini Configuração partilhada ELRS / ESP8285
src/lib/Ornithopter/ Mixer asa / motor — waveform, gearbox, filtro de canais
src/lib/Zephyrus/ Giroscópio (MPU6050 / LSM6DS3) + estabilizador Mesozoic
src/lib/ServoOutput/ Saída PWM sincronizada ao tick CRSF
src/lib/WIFI/ Servidor de configuração WebUI + PteroWebHandlers.cpp
src/lib/Mushin/ Ponte EP2 + RP2040 companion
src/html/ Fonte da WebUI (Vite + CoffeeScript + Haml/Lithaml)
src/python/ Scripts de build / pré-build, verificador de imagem
src/src/rx_main.cpp Ponto de entrada (loop RX do ELRS forkado)
src/user_defines.txt As suas overrides de compilação (gitignored)
src/user_defines.txt.example Modelo para o user_defines.txt
scripts/flash.sh Wrapper de build + flash num só comando
hermetic.manifest.md Missão, arquitetura e proibições de build

4 · Ordem de build (o que mais confunde)

O PteronautOS compila em duas etapas, e elas têm de correr nesta ordem:

Etapa Saída
WebUI src/html/headers/web-pteronautos-rx-8285.h
Firmware src/.pio/build/<env>/firmware.bin

O build do firmware corre o copy_html.py como passo pré-build, copiando o header da WebUI para o WebContent.h. Compile a WebUI primeiro, senão grava uma WebUI desatualizada na imagem.

Compilar a WebUI

cd src/html
nvm use 20
I18N_LOCALES=en npm run build:pteronautos

A variável I18N_LOCALES escolhe os idiomas embebidos:

I18N_LOCALES=en        npm run build:pteronautos   # English only (smallest)
I18N_LOCALES=en,de     npm run build:pteronautos   # English + German
I18N_LOCALES=all       npm run build:pteronautos   # all 11 languages

Compilar o firmware

cd ../.. && pio run -d src -e PteronautOS_ESP8285_2400_RX

O binário fica em src/.pio/build/PteronautOS_ESP8285_2400_RX/firmware.bin.

5 · Environments de target

Definidos em src/targets/pteronautos-rx.ini:

Environment Descrição
PteronautOS_ESP8285_2400_RX PWMP7, sem gyro (Mesozoic rate damper compilado mas off)
PteronautOS_ESP8285_2400_RX_HORIZON PWMP7, gyro + self-level (HORIZON) + baro
PteronautOS_ESP8285_2400_RX_PWMP5 PWMP5 (5 pads, GPIO5 = rádio BUSY)
PteronautOS_ESP8285_2400_RX_PWMP5_HORIZON PWMP5 + gyro + self-level + baro
PteronautOS_ESP8285_2400_RX_BARO Só barómetro (BMP180), sem gyro
PteronautOS_ESP8285_2400_RX_GEARBOX Variante gearbox (mixer profile 5)
PteronautOS_ESP8285_EP2_2400_RX EP2 + RP2040 (ponte companion MUSHIN)
PteronautOS_ESP8285_EP2_2400_RX_PWM EP2 standalone, RX/TX como 2 servos

Um build PWMP7 normal sem gyro:

pio run -e PteronautOS_ESP8285_2400_RX

Para adicionar self-level, compile o env _HORIZON (define ZEPHYRUS_ENABLED + MESOZOIC_HORIZON).

6 · Configuração em tempo de compilação

Duas formas de passar flags de build — elas somam-se.

src/user_defines.txt (as suas overrides — gitignored)

Copie o modelo e edite-o:

cp src/user_defines.txt.example src/user_defines.txt

Guarda os botões ajustáveis — binding phrase, WiFi, gyro, mixer profile, baud UART:

-DAUTO_WIFI_ON_INTERVAL=30
-DLOCK_ON_FIRST_CONNECTION
-DMIXER_PROFILE=1
-DZEPHYRUS_ENABLED=1
-DZEPHYR_IMU=ZEPHYR_IMU_MPU6050
-DMY_BINDING_PHRASE="my-binding-phrase"

O PlatformIO apanha isto automaticamente (build_flags.py) — sem flags na CLI. É exatamente isto que o flash.sh escreve por si.

Flags pontuais na linha de comandos

PLATFORMIO_BUILD_FLAGS="-DRegulatory_Domain_EU_CE_2400" \\
  pio run -e PteronautOS_ESP8285_2400_RX

O flash.sh usa este canal para o domínio regulatório; o resto vai pelo user_defines.txt.

Headers de afinação centrais

Para afinação profunda a nível de código (mapas de canais, limites de servo, ganhos do mixer), edite os headers diretamente:

  • src/lib/Ornithopter/OrnithopterConfig.h — mapa de canais, enum do mixer profile, limites de servo
  • src/lib/Zephyrus/ZephyrusConfig.h — I²C, IMU, AHRS/PID, ganhos do mixer

7 · Onde fazer alterações

Quer… Edite
Mudar o comportamento do mixer asa / motor src/lib/Ornithopter/OrnithopterGearbox.cpp (gearbox) ou Ornithopter.cpp (waveform de servo)
Adicionar / afinar a estabilização por gyro src/lib/Zephyrus/Zephyrus.cpp
Adicionar uma definição na WebUI src/html/src/pages/*.coffee + *.lithaml + locales/*.js, depois o JSON em PteroWebHandlers.cpp
Mudar a saída PWM src/lib/ServoOutput/devServoOutput.cpp
Mudar o loop de entrada do RX src/src/rx_main.cpp

Depois de alterar a fonte da WebUI, recompile a WebUI e depois o firmware.

8 · Regras de build (inegociáveis)

Do hermetic.manifest.md — o alvo é um ESP8285 de 1 MB, 80 MHz; cada feature paga o seu custo:

  • Nunca usar malloc / new — só stack e globais.
  • Nunca usar delay() — quebra o timing CRSF; tudo é assíncrono.
  • Nunca bloquear o loop principal.
  • Nunca remover o failsafe centrado — as asas voltam a 1500 µs se perder o link.
  • Manter-se abaixo de 65% RAM / 60% Flash.
  • Nunca adicionar GPS / VTX / waypoints / navegação — pertencem ao OrniFlight.

Os builds atuais do ESP8285 ficam perto dos 65% RAM (stack WiFi ELRS + Ornithopter + Zephyrus). Tenha cuidado com buffers e tabelas grandes.

9 · Referência rápida

# Fresh clone → first build (PWMP7, no gyro, English WebUI)
cd src/html && nvm use 20 && I18N_LOCALES=en npm run build:pteronautos
cd ../.. && cd src && pio run -e PteronautOS_ESP8285_2400_RX

# Build with gyro self-level
pio run -e PteronautOS_ESP8285_2400_RX_HORIZON

# Build PWMP5
pio run -e PteronautOS_ESP8285_2400_RX_PWMP5

# Inspect the full target list
pio run --list-targets

Para o fluxo de build-e-flash num só comando (e como o --no-build, os presets guardados e o bootloader funcionam), leia o guia do flash.sh .
