Developer 02

flash.sh — builds locais

A contrapartida num só comando do Flasher do browser: build, verificação e flash por UART — sem cloud.

O flash.sh percorre a mesma superfície de configuração do flasher web e do build cloud do GitHub Actions, e depois compila a WebUI, compila o firmware, verifica a imagem e grava-a por UART.

Para o caminho manual passo-a-passo, veja o guia de desenvolvimento .

1 · Pré-requisitos

Mesma toolchain do desenvolvimento — veja o guia de instalação da toolchain do ExpressLRS. Em resumo:

  • PlatformIO Core (pio)
  • Node.js 20 (nvm use 20)
  • Python 3
  • Um adaptador FTDI / série (ou ponte RP2040) ligado ao recetor

Utilizadores Windows: abra o Git Bash (instalado com o Git para Windows) e execute exatamente os mesmos comandos — ./scripts/flash.sh funciona sem alterações. A configuração única está descrita na página Developing.

2 · Arranque rápido — o wizard interativo

Sem flags, o script corre um wizard guiado (device → mixer → domain → gyro → idiomas) e depois compila + grava. Tudo o que o wizard pergunta também pode ser passado diretamente como flag:

./scripts/flash.sh

./scripts/flash.sh --device pwmp5 --mixer 1 --domain eu --gyro none --lang en

3 · One-liners comuns

Os comentários no bloco descrevem cada combinação de flags.

# Flash a PWMP5, 2-wings + crest rudder, no gyro, English WebUI
./scripts/flash.sh --device pwmp5 --mixer 1 --gyro none --lang en

# PWMP7 with rate-only gyro (Mesozoic damper)
./scripts/flash.sh --device pwmp7 --gyro rate

# Self-level (Horizon) gyro, German + English WebUI
./scripts/flash.sh --gyro horizon --lang de,en

# Skip the rebuild and flash the existing firmware.bin
./scripts/flash.sh --device pwmp5 --no-build

# Just probe the bootloader (no build, no flash)
./scripts/flash.sh --check

# List the catalogs
./scripts/flash.sh --list-devices --list-mixers --list-langs

4 · Flags principais

Device (--device)

Chave Hardware
pwmp5 PWMP5 — 5 pads de servo (GPIO0/1/3/9/10, GPIO5 = rádio BUSY)
pwmp7 PWMP7 — 6 pads de servo (GPIO0/1/3/9/10/5)
ep2pwm EP2 PWM — standalone, RX/TX (GPIO3/1) como 2 servos
mushin EP2 + RP2040 — ponte companion MUSHIN (9 ch)

Perfil de mixer (--mixer 0-13)

# Airframe
0 2 asas (waveform de batimento)
1 2 asas + leme de crista
2 4 asas (batimento frontal/traseiro)
3 V-tail + leme de cabeça (gearbox)
4 motor + V-tail (gearbox)
5 motor + V-tail + leme de cabeça (gearbox)
6 elevator + leme (gearbox)
7 motor + elevator + leme (gearbox)
8 motor + leme + cauda de rotação 3-servo (gearbox)
9 motor + leme + cauda split elevon 2-servo (gearbox)
10 motor + leme + cauda 1-pitch 1-rotate (gearbox)
11 motor + leme + cauda 2-servo fundida (gearbox)
12 Z-Wing 9-PWM (motor + leme + 4 asas + 3 cauda)
13 motor + cauda plana fundida (gearbox)

Domínio regulatório (--domain)

Chave Significado
eu EU CE 2400 — LBT (listen-before-talk, limitado)
ism ISM 2400 — banda ISM completa

Gyro (--gyro)

Chave Efeito
none sem gyro (padrão)
rate damper rate-only (Mesozoic)
horizon rate + self-level (Mesozoic HORIZON)

Os aliases antigos ainda funcionam: --mode none|rate|horizon e --horizon.

Chip IMU (--imu)

Chave Placa de sensor
mpu6050 GY-521 (MPU6050) — padrão
lsm6ds3 GY-LSM6DS3 (LSM6DS3)

5 · Flags de detalhe

A referência completa de flags (cada comentário explica a flag):

--binding-phrase <s>   # hardcoded binding phrase (empty = traditional bind)
--wifi-interval <n>    # WiFi auto-on seconds (-1 disables, default 30)
--device-name <s>      # device hostname
--wifi-ssid <s>        # home WiFi SSID (auto-join)
--wifi-pass <s>        # home WiFi password
--i2c-sda <gpio>       # IMU SDA (default 1)
--i2c-scl <gpio>       # IMU SCL (default 3)
--rotation <0-6>       # IMU board rotation
--pre-detect <0|1>     # probe SCL before I²C init (default 1)
--uart-baud <rate>     # CRSF UART baud (default 420000)
--baro <0|1>           # BMP180 barometer + altitude hold (shares gyro I²C bus)

Idiomas da WebUI (--lang / -l)

--lang en        # English only (smallest bundle)
--lang en,de     # English + German
--lang all       # all 11 languages
# omit --lang → interactive pick (or reuse saved settings)

Códigos disponíveis: en pt de es fr hi ja ko ru zh ar.

6 · Presets de configuração guardados

O script pode persistir uma configuração inteira num ficheiro gitignored (seguro para binding phrases / passwords WiFi):

# Save this run's config (prompts for a name)
./scripts/flash.sh --device pwmp5 --gyro none --save

# Save under a named preset
./scripts/flash.sh --device pwmp7 --gyro rate --save=turbo

# Reuse a saved preset (flags override saved defaults)
./scripts/flash.sh --conf=turbo --lang all

# Delete a saved preset
./scripts/flash.sh --conf=turbo --reset

Os ficheiros ficam em .pteronautos-flash-.conf. Sem --conf, um padrão guardado é oferecido interativamente ("Reusar definições guardadas?").

7 · --no-build e verificação de imagem

O --no-build salta a recompilação e grava o firmware.bin existente:

./scripts/flash.sh --device pwmp5 --no-build

Antes de gravar, o script corre o verify_pteronautos_image.py:

  • Build fresco (BUILD=1) — o .bin tem de corresponder exatamente às flags que acabou de passar (incluindo o mapa PWM de gyro on/off).
  • --no-build (BUILD=0) — o script confia no mapa de hardware embebido (--trust_embedded), por isso já não se queixa de mismatch só porque as suas flags atuais diferem do que o bin foi compilado.

Uma guarda é sempre imposta: a verificação --expect_product é derivada do --device, por isso não pode gravar acidentalmente uma imagem PWMP7 num PWMP5.

Se um build fresco falhar com "Hardware differs from project map", o bin em disco foi compilado com uma definição de gyro diferente — recompile (tire o --no-build), ou passe a flag --gyro correspondente.

8 · Flashing (bootloader)

O script localiza o esptool e a porta USB, e depois grava o firmware. Assume que o recetor já está em modo bootloader:

  1. Segure BOOT (GPIO0) no recetor.
  2. Faça power-cycle ao recetor (desligue os 3.3 V / USB → ligue de novo).
  3. Continue a segurar ~1 s, depois solte.

Dicas:

  • Desligue servos / carga externa da linha de 3.3 V enquanto grava — o ESP consome mais e pode dar brown out.
  • Se o flashing estiver instável, baixe o baud: --baud 9600.
  • Depois de gravar com sucesso, desligue e volte a ligar o recetor (não segure o GPIO0) para um boot normal.
  • Para verificar se o chip está vivo sem gravar: ./scripts/flash.sh --check.
